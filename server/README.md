# Jeju-Tour 사진 인증 서버 운영 안내

현재 프로젝트의 `server` 폴더가 서버입니다. 별도 DB 설치나 npm 패키지 설치 없이 **Node.js 24.14 이상 24.x 버전**으로 실행합니다. Node 내장 SQLite를 사용합니다([공식 문서](https://nodejs.org/docs/latest-v24.x/api/sqlite.html)). 이 버전에서 SQLite 실험 기능 안내가 출력될 수 있으며 서버 오류가 아닙니다.

## 1. 처음 실행

1. 서버로 사용할 컴퓨터에 [Node.js 24.x](https://nodejs.org/en/download)를 설치합니다.
2. **Jeju-Tour 폴더 전체**를 원하는 위치에 복사합니다. 예: `D:\프로그래밍\Jeju-Tour`. 드라이브 문자나 한글·공백 경로를 코드에서 고정하지 않았습니다.
3. `server\start-server.cmd`를 더블클릭합니다. 또는 프로젝트 폴더에서 `npm start`를 실행합니다.
4. `http://localhost:3000/course.html?panel=event`에 접속합니다. 기존의 **알림 → 이벤트**에서도 같은 화면을 사용합니다. 이벤트만 열려면 `http://localhost:3000/event.html`입니다.
5. 첫 실행 때 `server/config.json`, 데이터베이스와 참가자 폴더가 자동으로 만들어집니다.

일반 실행 창을 닫으면 서버가 종료됩니다. 수동 종료는 Ctrl+C입니다. HTML 파일을 탐색기에서 직접 열거나 기존 정적 호스팅만 사용하면 서버 저장은 작동하지 않습니다. 서버가 연결되지 않으면 화면에서 알려주고 신규 등록을 잠급니다.

## 2. 참가자의 사용 방법

- 이름, 운동 종류, 날짜, 운동 시간을 입력하고 사진을 선택한 뒤 **인증 등록**을 누릅니다.
- 사진은 선택 항목이며 JPG/PNG/WebP 최대 3장, 원본 장당 8MB까지 받습니다. HEIC는 JPG로 변환해서 올립니다. 화면에서 사진을 읽고 긴 변 2,000px 이내 JPEG로 저장하여 전송량을 줄이고 위치정보 등 EXIF를 제거합니다.
- **참가자 집계**에는 30분 이상 인증한 이름만 표시합니다. 같은 이름·같은 날짜의 30분 이상 기록은 여러 건이어도 1일 1점입니다. 30분 미만 기록 여러 건을 합산해 인증하지는 않습니다.
- 이름을 누르면 해당 참가자의 인증 내역으로 이동합니다. **인증 내역 → 참가자**에서도 선택할 수 있습니다. 30분 미만 기록만 있는 이름은 이 선택 목록에서 확인합니다.
- 사진을 누르면 크게 볼 수 있습니다. **전체 보기**로 전체 참가자의 내역을 다시 표시합니다.
- CSV는 현재 선택된 참가자 또는 전체 내역을 내려받습니다. 각 행은 개별 기록이므로 CSV의 행 수가 점수와 같지는 않습니다.
- 다른 기기에서 등록한 내역은 30초마다, 또는 **새로고침**을 누르거나 화면으로 돌아올 때 다시 불러옵니다.
- 사진 업로드가 끊기면 입력을 유지합니다. **같은 입력 그대로 다시 등록**하면 등록 식별자로 중복 저장을 방지합니다. 날짜가 같은 별도 인증은 내역에는 남되 점수는 중복 집계하지 않습니다.

이름의 앞뒤 공백과 중복 공백은 정리합니다. 동일한 이름은 한 참가자로 묶습니다. 동명이인은 `김민수(전주)`, `김민수(서울)`처럼 서로 다른 표기를 계속 사용해주세요. 별도의 참가자 로그인이나 본인 확인/관리자 승인 단계는 없습니다. 여기서 인증은 기존 규칙인 **30분 이상 운동 등록**을 뜻합니다.

## 3. 서버 폴더와 이름별 관리

```text
Jeju-Tour/
├─ event.html, event.js, event-config.js, ...  웹 페이지
└─ server/
   ├─ index.mjs                   웹 서버와 API
   ├─ config.json                 실제 설정과 관리자 키 (자동 생성, Git 제외)
   ├─ config.example.json         기본 설정 예시
   ├─ start-server.cmd            서버 실행
   ├─ backup-server.cmd           DB와 사진 백업
   ├─ export-records.cmd          이름별 JSON 및 통합 CSV 내보내기
   ├─ install-autostart.ps1       Windows 로그인 시 자동 실행 등록
   ├─ data/
   │  ├─ jeju-tour.sqlite         원본 데이터베이스
   │  ├─ jeju-tour.sqlite-wal     실행 중 생길 수 있는 DB 파일
   │  ├─ jeju-tour.sqlite-shm
   │  └─ participants/
   │     └─ p-홍길동--고유ID/
   │        └─ 2026-09-07/
   │           └─ 인증고유ID/
   │              ├─ record.json
   │              └─ 사진고유ID.jpg
   ├─ backups/날짜-시간-ID/        백업마다 별도 폴더
   ├─ exports/날짜-시간-ID/        이름별 인증 JSON과 통합 CSV
   └─ logs/                       자동 실행 시 로그
```

이름 뒤 고유 ID는 특수문자·동일 파일명 충돌을 피하기 위한 것입니다. 파일명은 이용자가 선택한 원본 파일명을 사용하지 않습니다. 사진이 없는 인증도 이름별 폴더에 `record.json`을 남깁니다. 폴더명이나 파일을 직접 바꾸면 DB와 연결이 끊길 수 있으므로 변경하지 마세요.

**DB가 원본입니다.** 개별 `record.json`은 등록 시점의 읽기용 사본입니다. 이후 삭제 여부를 포함한 현재 상태는 화면, DB 또는 `export-records.cmd`로 내보낸 결과에서 확인합니다.

## 4. 관리자 관리

1. `server/config.json`의 `adminToken` 값을 확인합니다. 처음 실행할 때 무작위로 생성되며 웹으로 공개하지 않습니다.
2. 이벤트 화면 하단 **운영자 관리**를 열어 관리자 키를 입력하고 연결합니다.
3. 인증 내역에 나타나는 **인증 삭제**로 잘못 등록된 항목을 개별 삭제합니다. 참가자 점수도 다시 계산됩니다.
4. 작업을 마치면 관리자 연결을 해제합니다. 키는 브라우저 저장소에 저장하지 않으며 새로고침하면 연결이 해제됩니다.

삭제는 DB의 `deleted_at`을 기록해 화면과 사진 API에서 숨기는 방식입니다. 원본 사진은 백업·복구를 위해 보존합니다. 되살려야 할 경우 서버를 중지하고 먼저 백업한 뒤 SQLite 관리 도구에서 해당 인증 ID의 `deleted_at`을 NULL로 돌릴 수 있습니다. 일반 참가자 화면에 전체 삭제 기능은 제공하지 않습니다.

## 5. 다른 휴대폰/컴퓨터 연결

같은 공유기의 기기가 접속하려면 서버를 종료하고 `server/config.json`의 `host`를 `"0.0.0.0"`으로 바꾼 후 재실행합니다. Windows의 `ipconfig`로 서버 PC의 IPv4 주소를 확인하고 휴대폰에서 `http://서버PC주소:3000/event.html`을 엽니다. Windows 방화벽은 사용할 사설 네트워크에서 해당 포트의 연결을 허용해야 합니다. 기본값 `127.0.0.1`은 서버 PC 안에서만 접속됩니다.

서로 다른 장소에서 사용할 때는 서버의 고정된 HTTPS 주소가 필요합니다. 도메인/HTTPS 리버스 프록시를 실제 운영 PC에 연결하고 이 Node 서버로 전달합니다. 서버 자체는 HTTP를 제공합니다. 실제 외부 주소와 PC가 아직 정해지지 않아 외부 공개와 방화벽 변경은 자동으로 하지 않습니다.

페이지와 API를 같은 서버에서 제공하면 `event-config.js`를 수정할 필요가 없습니다. 기존 정적 사이트와 서버를 분리해 운영할 경우:

1. 정적 사이트의 `event-config.js`에서 `window.JEJU_EVENT_API_BASE = 'https://인증서버주소';`로 지정합니다. 끝에 `/api`를 붙이지 않습니다.
2. 서버 `config.json`의 `allowedOrigins`에 정적 사이트의 정확한 출처를 넣습니다. 예: `["https://example.github.io"]`. 경로와 끝 슬래시는 넣지 않습니다.
3. 서버를 재시작하고 정적 사이트 파일을 다시 배포합니다. HTTPS 페이지에서는 HTTP 서버를 호출할 수 없습니다.

현재 정책은 참가자가 서로 이름·운동기록·사진을 볼 수 있는 공유 이벤트입니다. 관리자 키는 삭제 기능만 보호합니다. 인터넷에 공개하면 주소를 아는 사람은 참가자 기록을 보고 등록할 수 있으므로 참가자 전용 운영이 필요하면 앞단의 접근 인증을 적용해야 합니다.

## 6. 백업과 다른 컴퓨터로 이전

**정기 백업**: `backup-server.cmd` 또는 `npm run backup`. 서버가 켜진 상태에서도 SQLite의 백업 기능으로 DB 스냅샷을 만들고 사진 폴더를 복사합니다. `BACKUP-COMPLETE.txt`가 있는 폴더만 완료된 백업입니다. 전체 백업을 외장 드라이브나 별도 장치에도 복사해 두세요. 백업은 자동 삭제되지 않습니다.

**전체 이전(권장)**:

1. 기존 서버를 중지합니다. 자동 실행을 등록했다면 `Stop-ScheduledTask -TaskName Jeju-Tour-Server` 후 다시 켜지지 않도록 해당 작업을 비활성화합니다.
2. 백업을 만듭니다. `server/data`, 실제 `server/config.json`, 모든 웹 파일을 포함한 **Jeju-Tour 전체 폴더**를 새 컴퓨터의 `D:\프로그래밍\Jeju-Tour` 등 원하는 위치로 복사합니다. `.git`, `.test-output`, `node_modules`는 운영에 필요하지 않습니다.
3. 새 컴퓨터에 Node.js 24.x를 설치합니다. 설정의 `dataDir: "./data"`, `backupDir: "./backups"`를 유지하면 경로 변경이 필요 없습니다. 별도 절대 경로를 지정한 적이 있다면 새 PC에 맞게 바꿉니다.
4. 서버를 실행하고 인증 개수, 참가자 이름, 사진이 보이는지 확인합니다.
5. 새 PC의 IP·방화벽·외부 주소를 연결합니다. 두 PC를 동시에 등록용으로 열면 서로 다른 DB에 저장되므로 하나만 운영합니다.
6. 자동 실행 작업은 새 위치에서 다시 등록합니다.

**백업에서 복원**: 서버를 중지하고 현재 `data`는 별도 보관합니다. 새 빈 `data` 폴더에 완료된 백업의 `jeju-tour.sqlite`와 `participants`를 함께 복사하고 실행합니다. 기존 DB의 `-wal`/`-shm` 파일을 섞지 마세요. 운영 기간 설정은 백업의 `backup-info.json`을 참고해 `config.json`에 맞춥니다. 관리자 키는 백업에 포함하지 않으므로 기존 `config.json`을 안전하게 함께 보관하거나 새 키를 사용합니다.

## 7. Windows 자동 실행(선택)

최종 설치 위치에서 관리자 PowerShell을 열고 실행합니다:

```powershell
powershell -ExecutionPolicy Bypass -File ".\server\install-autostart.ps1"
Start-ScheduledTask -TaskName Jeju-Tour-Server
```

현재 Windows 계정으로 **로그인할 때** 숨김 창으로 시작합니다. 로그인 전 부팅 단계의 Windows 서비스는 아닙니다. 수동 실행 중인 서버를 먼저 종료해야 같은 포트로 중복 실행되지 않습니다. 종료/제거는 다음 명령을 사용합니다:

```powershell
Stop-ScheduledTask -TaskName Jeju-Tour-Server
Unregister-ScheduledTask -TaskName Jeju-Tour-Server
```

자동 실행 실패 시 `server/logs`와 작업 스케줄러 기록을 확인합니다. PC 이동 후에는 새 경로에서 자동 실행 스크립트를 다시 실행하세요.

## 8. 기존 브라우저 기록 가져오기

이전 `localStorage` 기록이 남아 있는 브라우저에서 **이 브라우저의 기존 기록 가져오기**를 누릅니다. 동일 기록을 다시 가져와도 중복 저장하지 않고 브라우저 원본도 삭제하지 않습니다. 오류가 발생한 항목은 실패 건수와 오류를 알려줍니다. 기존 기록에는 사진이 없으므로 사진 없이 가져옵니다.

브라우저 저장소는 주소별로 분리되어 있습니다. 기존 정적 사이트의 주소에서 기록을 저장했다면 그 주소에 갱신된 이벤트 페이지와 `event-config.js`를 배포하여 서버를 연결한 상태에서 가져오세요. `localhost`로 주소만 바꾸면 이전 주소의 기록은 자동으로 읽을 수 없습니다.

## 9. 설정과 점검

`config.json`의 `eventStart`, `eventEnd`로 운영 기간을 바꾸고 서버를 재시작할 수 있습니다. 주별 점수는 시작일을 기준으로 7일 단위입니다. 기간을 변경해도 기존 데이터는 삭제하지 않습니다. 새 이벤트를 독립 운영하려면 백업 후 새 `dataDir`을 지정하세요.

```powershell
npm test
npm run backup
npm run export
```

API 테스트는 실제 임시 DB·사진을 사용해 저장, 이름 정규화, 중복 요청, 점수, 입력/용량 검증, 관리자 권한, 경로 보호, 재시작, 다른 경로로 백업 복원을 점검합니다. 운영 데이터는 사용하지 않습니다.

- `EADDRINUSE`: 같은 포트의 서버가 실행 중입니다. 기존 실행을 종료하거나 `port`를 변경하세요.
- 서버 연결 안 됨: 실행 창/작업 상태, 주소, 방화벽, `event-config.js`를 확인하세요.
- 사진 업로드 실패: 파일 종류·용량·서버 디스크 공간을 확인하세요. 프록시를 사용하는 경우 업로드 한도는 25MB 이상, 제한 시간은 60초 이상으로 설정하세요.
- 기록이 없어 보임: 접속 서버와 `config.json`의 `dataDir`이 기존 데이터 위치인지 확인하세요. DB만 옮기고 사진 폴더를 누락하지 않았는지도 확인합니다.
